# 多会话协作流程

## 基本角色

| 角色 | 职责 | 产出 |
| --- | --- | --- |
| 用户 | 确定目标、约束、重大方向与需确认事项 | 可追溯的明确指示 |
| 总协调 | 拆分工作、处理依赖、检查状态、验收与同步 | 项目基线、任务分派、简短汇报 |
| 专题会话 | 在明确边界内推进某一工作线 | 报告、代码、证据、状态更新 |
| 子代理 | 对一个限定问题开展分析、实现或复核 | 结论、证据位置、未决事项 |

专题会话拥有独立聊天上下文，但可能共用同一工作目录和宿主资源。子代理不是自动拥有完整项目知识的共享大脑。派单应说明目标、输入、范围、约束、交付位置和完成标准；不要让并发任务编辑同一份文件。

## 状态与证据

- 将用户明确决定、第三方陈述、源码观察、推断、独立复核、实际运行及业务验收分开写。
- 每个状态写明记录时间、负责人、来源和可验证产物；旧快照不代表当前环境。
- 保留历史决定及被取代关系，保留失败、未确认和无法读取的范围。
- 消息送达、Agent 结束、测试设计完成、测试通过和业务验收是不同状态。
- 原始材料的使用和公开需遵守来源授权；不要把凭据、个人数据、内部资料或聊天日志默认放进公开仓库。

## 方向变化

1. 收到新信息的会话核对来源：是用户明确决定，还是第三方材料／推断。
2. 对明确决定，列出受影响的工作、旧决定和应停止或调整的任务。
3. 取得共享状态的写入权，更新决策和状态，保留旧记录。
4. 通知总协调及必要的专题会话；记录送达与接入确认，不能将送达当成完成。
5. 信息含糊或冲突重大时，向用户确认；在相关分支暂停，不扩大原有授权。

## 会话恢复

1. 读取项目入口、最新决策和当前状态。
2. 核对用户当前指示、已有授权、任务负责人和输入版本。
3. 确认是否已有其他会话正在处理，检查证据和已完成产物。
4. 简短汇报当前方向、可继续事项和阻塞；在授权范围内接续。
5. 维护断点：已完成工作、产物、来源、待解决问题和下一步。

不要因为任务标为“进行中”或锁已过期就自动恢复；确认原工作者及相关进程已停止后，依照实际工具规则处理。

## 并行策略

- 不重叠的阅读、分析和独立复核可以并行。
- 同一份共享状态在同一时间只允许一个合作写入者。
- 同一实例、硬件或图形会话等共享资源按实际能力串行；不要用更多 Agent 绕过共享资源限制。
- 子代理数量依据资源、成本和整合能力确定；更多并发不自动等于更高效率。
- 独立复核需由非作者执行，限定复核版本和范围；复核通过不等于目标环境已经验证。

## 后台任务

如果工具平台支持定时恢复，可以定期读取最新状态并在已有授权内推进；静默处理无变化的检查，对完成、失败、冲突或需要用户决定的事项报告。电脑离线、应用关闭、会话忙碌或调度机制不支持时，实际触发和补跑行为应以平台运行记录为准，不假设连续在线。
